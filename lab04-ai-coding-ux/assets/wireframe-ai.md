# Text wireframe — AI draft

สถานะ: ร่างจาก persona จำลอง ต้องให้ทีมตรวจหลังสัมภาษณ์จริง

## คำสั่งที่ใช้เป็นโจทย์ออกแบบ
ออกแบบ Login, Dashboard และ Add Product สำหรับพนักงานคลังทักษะ 2/5 ใช้ PC รองรับสินค้าจับต้องได้และไฟล์ดิจิทัล มี label, required, error พร้อมวิธีแก้ และ success state ใช้สีตามโจทย์และมีลำดับ Tab ชัดเจน

## 1. Login
```text
OMEGA INVENTORY
เข้าสู่ระบบ
ชื่อผู้ใช้ * [________________]
รหัสผ่าน * [________________] [แสดงรหัสผ่าน]
! ชื่อผู้ใช้: กรุณากรอกชื่อผู้ใช้ในช่องนี้
! รหัสผ่าน: รหัสผ่านไม่ถูกต้อง กรุณาลองอีกครั้ง
[เข้าสู่ระบบ]
หากเข้าระบบไม่ได้ ติดต่อผู้ดูแล
```
Label ไม่หายเมื่อพิมพ์ ปุ่มมีชื่อชัด และข้อความผิดพลาดไม่เปิดเผยว่าบัญชีใดมีอยู่. แก้จากร่างแรกที่รวม error ของสองช่องเป็นข้อความเดียว

## 2. Dashboard
```text
OMEGA INVENTORY | ภาพรวม | เพิ่มสินค้า | ออกจากระบบ
ภาพรวมคลังสินค้า                          [เพิ่มสินค้า]
[สินค้าจับต้องได้ 24] [ไฟล์ดิจิทัล 6] [สต็อกต่ำ 3]
ค้นหา [ชื่อหรือรหัส]  ชนิด [ทั้งหมด v]
รหัส | ชื่อ | ชนิด | คงเหลือ | สถานะ
P001 | ปากกา | จับต้องได้ | 4 ชิ้น | ! สต็อกต่ำ
D001 | แบบฝึกหัด | ไฟล์ดิจิทัล | ไม่จำกัด | พร้อมขาย
ไม่มีข้อมูล: ยังไม่มีสินค้าในระบบ [เพิ่มสินค้ารายการแรก]
```
ตัวเลขทั้งหมดเป็นข้อมูลตัวอย่าง สถานะมีข้อความร่วมกับสี และไฟล์ดิจิทัลไม่ถูกนับเป็นสต็อกต่ำ

## 3. Add Product
```text
เพิ่มสินค้า
* จำเป็นต้องกรอก
ชื่อสินค้า * [____________]  รหัสสินค้า * [____________]
ชนิดสินค้า * (o) จับต้องได้ ( ) ไฟล์ดิจิทัล
หมวดหมู่ [เลือกหมวดหมู่ v]  ราคา * [_______] บาท
ถ้าจับต้องได้: จำนวนเริ่มต้น * [___] ชิ้น  จุดแจ้งเตือน [___] ชิ้น
ถ้าดิจิทัล: ไฟล์สินค้า * [เลือกไฟล์] — ไม่ตัด stock เมื่อขาย
รูปสินค้า (ไม่บังคับ) [เลือกภาพ]
! ใต้ช่องราคา: กรอกตัวเลขมากกว่า 0 บาท
[ยกเลิก]                                  [บันทึกสินค้า]
สำเร็จ: บันทึก ปากกา (P001) แล้ว [กลับไปดูรายการ]
```
ตัวอย่างยืนยันคำสั่งซื้อ: จับต้องได้แสดงจำนวนและสถานะจัดส่ง; ดิจิทัลแสดงว่าเปิดดาวน์โหลดหลังยืนยันคำสั่งซื้อแล้วเท่านั้น. แก้จากร่างแรกที่วาง error ราคาแยกจากช่องและทำให้ข้อมูลตามชนิดสินค้าแยกชัดเจนขึ้น

## ลำดับ Tab ที่เสนอ
Login: ชื่อผู้ใช้ → รหัสผ่าน → แสดงรหัสผ่าน → เข้าสู่ระบบ
Add Product: ชื่อ → รหัส → ชนิด → หมวด → ราคา → จำนวน/ไฟล์ → threshold (เฉพาะจับต้องได้) → รูป → ยกเลิก → บันทึก
นี่เป็นลำดับที่ออกแบบ ยังไม่ใช่ผลทดสอบ keyboard ของโปรแกรมจริง
