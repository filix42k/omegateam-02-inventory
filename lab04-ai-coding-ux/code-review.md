ไฟล์ที่ review: inventory_service.py (โค้ดต้นฉบับของผู้สอน ไม่แก้ไข)

## Comments

### 1. `sell_batch`, บรรทัด 18–21 — correctness / high
ปัญหา: เมธอดตัด stock ทีละรายการทันที จึงไม่เป็น batch แบบสำเร็จหรือล้มเหลวทั้งชุด หากรายการหลังผิดพลาด รายการก่อนถูกตัดไปแล้ว
กรณีพัง: A=10, B=2; `sell_batch({'A': 3, 'B': 5})` จะตัด A เหลือ 7 ก่อน `sell('B', 5)` โยน ValueError ทำให้ A ถูกขายไปทั้งที่คำสั่งล้มเหลว
เสนอแก้: ตรวจความถูกต้องและ stock ของทุกรายการก่อน แล้ว commit การเปลี่ยนแปลงทั้งหมดภายใต้ lock/กลไก transaction

### 2. `reserve`, บรรทัด 29–30 — correctness / high
ปัญหา: ไม่ตรวจ `amount > 0`; จำนวนติดลบผ่านเงื่อนไขและลดค่าจอง ทำให้ยอดที่จองได้เพิ่มอย่างผิดจริง
กรณีพัง: มี 10 ชิ้น, จอง -4; `_reserved` กลายเป็น -4 และรายงานยอดจองได้ 14 ชิ้น
เสนอแก้: ปฏิเสธจำนวน <= 0 ก่อนแก้ state และทดสอบค่าศูนย์/ค่าติดลบ

### 3. `reserve`, บรรทัด 27–31 — concurrency / high
ปัญหา: อ่านยอดจองและเขียนยอดจองโดยไม่มี lock; สองคำขออาจอ่านยอดเดิมแล้วเขียนทับกัน ทำให้การจองหนึ่งรายการหาย
กรณีพัง: มี 10 ชิ้น `_reserved=0`; thread A และ B จอง 6 พร้อมกัน ทั้งคู่เห็น 0 และเขียน 6; ระบบรับคำขอ 12 ชิ้นแต่บันทึกเพียง 6
เสนอแก้: ใช้ lock ครอบการอ่าน ตรวจเงื่อนไข และเขียน `_reserved` เป็นขั้นตอนเดียว

### 4. `items_in_price_range`, บรรทัด 38 — correctness / medium
ปัญหา: docstring ระบุช่วงปิด `[low, high]` แต่ใช้ `<` ตัดรายการที่ราคาตรงกับปลายช่วงออก
กรณีพัง: `low=10, high=20`; สินค้าราคา 10 หรือ 20 ไม่ถูกรวม ทั้งที่ควรอยู่ในช่วง
เสนอแก้: ใช้ `low <= item.price <= high` และเพิ่ม boundary tests

### 5. `low_stock_report`, บรรทัด 47 — correctness / medium
ปัญหา: docstring บอก “ต่ำกว่าหรือเท่ากับ” แต่เงื่อนไขเช็กแค่ต่ำกว่า
กรณีพัง: threshold=5, stock=5; สินค้าไม่ปรากฏในรายงานทั้งที่ docstring บอกว่าต้องปรากฏ
เสนอแก้: ใช้ `<=` หรือแก้ docstring หากความหมายที่ต้องการคือ “ต่ำกว่า”

### 6. `concurrent_restock`, บรรทัด 54–56 — concurrency / high
ปัญหา: อ่าน `current` ก่อนเข้า lock ทำให้ lock คุ้มครองเฉพาะการเขียน ไม่ได้ทำให้ read-modify-write เป็น atomic
กรณีพัง: stock เริ่ม 10; สอง thread เติม 1 พร้อมกันและอ่าน 10 ทั้งคู่ จากนั้นเขียน 11 ทั้งคู่ ผลสุดท้าย 11 แทน 12
เสนอแก้: ย้ายการอ่านค่าเข้าไปใน lock และให้ทุกทางที่แก้ stock ใช้ lock เดียวกัน

### 7. `average_unit_value`, บรรทัด 63–64 — correctness / medium
ปัญหา: ชื่อและ docstring บอกค่าเฉลี่ยต่อชิ้น แต่หารด้วยจำนวนชนิดสินค้า แทนจำนวนชิ้นทั้งหมด; ยังหารศูนย์เมื่อคลังว่าง
กรณีพัง: สินค้า A ราคา 10 จำนวน 10 และ B ราคา 20 จำนวน 1; ค่าต่อชิ้นที่ถ่วงตามจำนวนควรเป็น 120/11 ≈10.91 แต่โค้ดคืน 60; ถ้าไม่มีรายการจะเกิด ZeroDivisionError
เสนอแก้: หารด้วยผลรวม quantity และกำหนดผลลัพธ์เมื่อไม่มีสินค้า เช่น 0.0 ตามสัญญา API

### 8. `reserve`, `items_in_price_range`, `low_stock_report`, `concurrent_restock`, `average_unit_value` — style / low
ปัญหา: หลายเมธอดเข้าถึง `_inv._items` ซึ่งเป็นรายละเอียดภายในของ Inventory โดยตรง ทำให้ service ผูกกับโครงสร้าง private และเปลี่ยน implementation แล้วพังได้
กรณีพัง: Inventory เปลี่ยนจาก dict เป็น repository หรือเปลี่ยนชื่อ `_items`; เมธอดเหล่านี้ล้มทันทีแม้ API สาธารณะยังรองรับงานเดิม
เสนอแก้: เพิ่ม public methods ที่จำเป็นใน Inventory หรือส่ง dependency ที่มี interface ชัดเจน
