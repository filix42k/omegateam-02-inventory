# Spec: ฟีเจอร์แจ้งเตือนสต็อกต่ำ และรายงานมูลค่าสต็อก

## 1. เป้าหมาย (Goal)

เพิ่มความสามารถให้ระบบ inventory แจ้งเตือนผู้จัดการเมื่อสินค้าใดต่ำกว่า threshold และให้ผู้จัดการดูรายงานมูลค่าสต็อกแยกตามหมวดหมู่ได้

## 2. User Story

| รหัส | User Story |
|---|---|
| US-01 | As a พนักงานคลังสินค้า, I want บันทึกการรับ/จ่ายสินค้าพร้อมอัปเดตสต็อกทันที, so that สต็อกในระบบสะท้อนจำนวนจริง |
| US-02 | As a ผู้จัดการ, I want รับการแจ้งเตือนทันทีเมื่อสินค้าใดต่ำกว่า threshold, so that สั่งซื้อได้ก่อนของหมด |
| US-03 | As a ผู้จัดการ, I want ดูมูลค่ารวมของสต็อกแยกตามหมวดหมู่, so that ตัดสินใจด้านการเงินได้ |
| US-04 | As a ผู้จัดการ, I want ตั้งค่าจุดสั่งซื้อ (Threshold) แยกตามสินค้าย่อยแต่ละรายการได้, so that สินค้าที่มีปริมาณการใช้งานต่างกันมีการแจ้งเตือนที่เหมาะสม |
| US-05 | As a ผู้จัดการ, I want เลือกช่องทางการรับการแจ้งเตือน (Email หรือ SMS) ตั้งค่าเป็นรายสินค้าได้, so that รับทราบสถานะสต็อกผ่านช่องทางที่สะดวกที่สุด |

## 3. Acceptance Criteria (Given-When-Then)

### AC ของ US-02 (ตัวอย่างที่ผู้สอนกำหนด)

```gherkin
Scenario: จ่ายสินค้าจนสต็อกต่ำกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 20 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 8 เมตร
  Then สต็อกคงเหลือ 12 เมตร
  And ระบบส่งการแจ้งเตือนถึงผู้จัดการว่าสต็อกต่ำ

Scenario: จ่ายสินค้าโดยสต็อกยังสูงกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 50 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then สต็อกคงเหลือ 40 เมตร
  And ระบบไม่ส่งการแจ้งเตือน

Scenario: จ่ายสินค้าแล้วสต็อกเท่ากับ threshold พอดี
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 25 เมตร และ threshold = 15
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then สต็อกคงเหลือ 15 เมตร
  And ระบบไม่ส่งการแจ้งเตือน (เนื่องจากสต็อกยังไม่ต่ำกว่า threshold)
```

### AC ของ US-01

```gherkin
Scenario: บันทึกรับสินค้าเข้าสต็อกสำเร็จ
  Given สินค้า "ท่อ PVC 1/2 นิ้ว" มีสต็อกคงเหลือ 10 ท่อน
  When พนักงานบันทึกรับเข้า 5 ท่อน
  Then สต็อกคงเหลืออัปเดตเป็น 15 ท่อนทันที

Scenario: ปฏิเสธการจ่ายสินค้าออกเมื่อจำนวนคงเหลือไม่พอ
  Given สินค้า "ท่อ PVC 1/2 นิ้ว" มีสต็อกคงเหลือ 5 ท่อน
  When พนักงานบันทึกจ่ายออก 10 ท่อน
  Then ระบบปฏิเสธรายการ และแสดงข้อความ "จำนวนคงเหลือไม่พอ"
  And สต็อกคงเหลือยังคงเป็น 5 ท่อนเท่าเดิม
```

### AC ของ US-03

```gherkin
Scenario: คำนวณมูลค่ารวมสต็อกแยกตามหมวดหมู่ถูกต้อง
  Given มีสินค้าในหมวด "งานไฟฟ้า" รวมมูลค่า 5,000 บาท และหมวด "งานประปา" รวมมูลค่า 3,000 บาท
  When ผู้จัดการสั่งเรียกดูรายงานมูลค่าสต็อก
  Then ระบบแสดงมูลค่ารวมหมวด "งานไฟฟ้า" เท่ากับ 5,000 บาท หมวด "งานประปา" เท่ากับ 3,000 บาท
  And มูลค่ารวมทั้งสิ้นเท่ากับ 8,000 บาท

Scenario: เรียกดูรายงานเมื่อยังไม่มีสินค้าในระบบ
  Given ยังไม่มีข้อมูลสินค้าในระบบ
  When ผู้จัดการสั่งเรียกดูรายงานมูลค่าสต็อก
  Then ระบบแสดงข้อความ "ยังไม่มีข้อมูลสินค้าในระบบ" และมูลค่ารวมเท่ากับ 0 บาท
```

### AC ของ US-04

```gherkin
Scenario: ตั้งค่า Threshold ใหม่ให้สินค้าเฉพาะรายการสำเร็จ
  Given สินค้า "สวิตช์ไฟ 2 ทาง" มี Threshold เดิม = 10
  When ผู้จัดการเปลี่ยนตั้งค่า Threshold เป็น 5
  Then ระบบบันทึก Threshold ใหม่เป็น 5 ทันที
```

### AC ของ US-05

```gherkin
Scenario: เลือกช่องทางแจ้งเตือนเป็น Email และ SMS สำหรับสินค้าเฉพาะรายการ
  Given สินค้า "สายไฟ 2.5 sq.mm" ตั้งค่าการแจ้งเตือนเป็น "Email"
  When ผู้จัดการเปลี่ยนการตั้งค่าแจ้งเตือนเป็น "SMS"
  Then เมื่อสต็อกต่ำกว่า Threshold ระบบจะส่งการแจ้งเตือนผ่านช่องทาง "SMS"
```

## 4. In Scope / Out of Scope

**In Scope:**
- บันทึกรับ/จ่าย + อัปเดตสต็อกใน memory
- การแจ้งเตือนสต็อกต่ำผ่าน Email และ SMS (ใช้การ print แทนการส่งจริงใน Lab นี้)
- รายงานมูลค่ารวมสต็อกแยกตามหมวดหมู่สินค้า
- ตั้งค่า Threshold และช่องทางแจ้งเตือนแยกรายสินค้า

**Out of Scope:**
- การส่ง Email หรือ SMS จริงไปยังระบบเครือข่ายภายนอก
- ระบบยืนยันตัวตน (Authentication / Login) และระบบจัดการสิทธิ์ผู้ใช้งาน
- การเชื่อมต่อฐานข้อมูลถาวรภายนอก (Database Server)

## 5. Functional Requirements (FR)

| รหัส | ความต้องการ | จาก Story |
|---|---|---|
| FR-01 | ระบบต้องอัปเดตสต็อกทันทีหลังบันทึกรับ/จ่าย | US-01 |
| FR-02 | ระบบต้องตรวจสต็อกก่อนจ่าย และปฏิเสธถ้าไม่พอ | US-01 |
| FR-03 | ระบบต้องแจ้งเตือนเมื่อสต็อกหลังจ่ายต่ำกว่า threshold | US-02 |
| FR-04 | ระบบต้องคำนวณและแสดงมูลค่าสต็อกรวมแยกตามหมวดหมู่สินค้าได้ | US-03 |
| FR-05 | ระบบต้องรองรับการตั้งค่า Threshold และช่องทางแจ้งเตือน (Email/SMS) แยกรายสินค้า | US-04, US-05 |

## 6. Non-Functional Requirements (NFR)

| รหัส | มิติ | ความต้องการ (ต้องวัดได้) |
|---|---|---|
| NFR-01 | Performance | รายงานมูลค่าสต็อก 1,000 รายการเสร็จภายใน 1 วินาที |
| NFR-02 | Maintainability | เพิ่มช่องทางแจ้งเตือนใหม่ได้โดยไม่แก้ business logic เดิม |
| NFR-03 | Reliability | เมื่อระบบเกิดข้อผิดพลาดในการคำนวณ ต้องไม่กระทบต่อข้อมูลคงเหลือเดิมในระบบ |

## 7. Design Notes

- การแจ้งเตือนต้องแยกออกจาก business logic ของสต็อก
- คาดว่าจะมีหลายช่องทางแจ้งเตือน ควรออกแบบให้เพิ่มได้ง่าย (ใช้ Notifier Interface / Factory Pattern)
